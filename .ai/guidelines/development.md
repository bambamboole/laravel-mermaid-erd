# Local Development

- Run the full CI-equivalent gate with `composer check` (Pint, PHPStan level 8, Rector dry-run,
  Pest). Never push on red.
- PHPStan runs at level 8 over `src`, `tests` and `workbench/app`. `src` is clean without
  suppressions; `phpstan.neon.dist` ignores only the union/nullable identifiers under `tests/` that
  PHPStan cannot narrow through Laravel's test helpers. Never widen those ignores to `src`.
- Tests live in `tests/Feature` and `tests/Unit`, plus the `Arch` suite in `tests/ArchTest.php` —
  the phpunit test suites pick up only those, so a test file dropped straight into `tests/` silently
  never runs. Reach package files with `Orchestra\Testbench\package_path()`, never `__DIR__` walks.
- The dev tooling is generated by `vendor/bin/testbench package:init` from
  `bambamboole/extended-testbench`; CI gates drift with `package:init --check`. Run that before
  changing `phpunit.xml.dist`, `rector.php`, `pint.json`, `.gitattributes` or the composer scripts —
  a hand edit there will fail the gate. Deliberate divergence gets baselined under
  `extra.extended-testbench.check-ignore` in `composer.json`, where `phpstan.neon.dist` already
  sits (our level 8 + mockery extension + test ignores are intentional, the scaffold ships level 6).
  `.github/workflows/ci.yml` is checked for existence only, so the MySQL and Postgres jobs added on
  top of the generated matrix are safe there.
- Tests run against in-memory SQLite by default. CI additionally runs the whole suite against
  MySQL 8 and Postgres 16; locally, start a container and set `DB_CONNECTION`, `DB_HOST`, `DB_PORT`,
  `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` (see `tests/TestCase.php`).
- **Assertions on generated diagrams must stay driver-agnostic.** Column type names differ per
  driver (`integer` vs `bigint` vs `int8`) and defaults render differently (Postgres emits
  `nextval(...)`). Match constraint markers (`\w+ id PK`), never concrete type names.
- The example ERD in `README.md` is generated from the full workbench schema. Regenerate it whenever
  the workbench migrations or the diagram output format change:
  `vendor/bin/testbench workbench:build && vendor/bin/testbench generate:mermaid-erd --output=file --path=$PWD/README.md`
  If that errors with "no commands defined in the generate namespace", the cached package manifest
  was purged (`package:purge-skeleton` runs on every `post-autoload-dump`); rebuild it with
  `vendor/bin/testbench package:discover`.
